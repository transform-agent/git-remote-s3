# Translation Plan: git-remote-s3 → Elixir

## 1. Source Language & Frameworks

| Dimension | Detail |
|-----------|--------|
| **Language** | Python 3.10+ |
| **Build tool** | Poetry (`pyproject.toml`) |
| **Key runtime deps** | `boto3` / `botocore` (AWS SDK for Python), `urllib3` |
| **Dev/test deps** | `pytest`, `mock`, `flake8`, `mypy`, `black`, `coverage` |
| **Entry points** | `git-remote-s3` → `remote:main`, `git-lfs-s3` → `lfs:main`, `git-s3` → `manage:main` |

The project is a **git remote helper** (a subprocess that Git spawns and communicates with over stdin/stdout using a line-based protocol). It also ships a **Git LFS custom transfer agent** and a **management CLI**.

---

## 2. Target Language & Framework

| Dimension | Detail |
|-----------|--------|
| **Language** | Elixir 1.15+ / OTP 26 |
| **Build tool** | Mix |
| **AWS SDK** | [`ex_aws`](https://hex.pm/packages/ex_aws) + [`ex_aws_s3`](https://hex.pm/packages/ex_aws_s3) (equivalent to boto3/botocore) |
| **HTTP adapter** | [`hackney`](https://hex.pm/packages/hackney) (used by ex_aws) |
| **JSON** | [`jason`](https://hex.pm/packages/jason) (replaces Python `json`) |
| **CLI arg parsing** | [`optparse_options`](https://hex.pm/packages/optparse_options) or stdlib `OptionParser` |
| **Test framework** | `ExUnit` (built-in) with [`Mox`](https://hex.pm/packages/mox) for mocking |
| **Concurrency** | Elixir `Task` + `Task.async_stream` (replaces `concurrent.futures.ThreadPoolExecutor`) |

## 6. Key Translation Decisions

### 6.1 UriScheme
Python uses an `Enum`. In Elixir we use module constants / atoms:
```elixir
defmodule GitRemoteS3.UriScheme do
  @s3     :s3
  @s3_zip :s3_zip
  def s3,     do: @s3
  def s3_zip, do: @s3_zip
end
```

### 6.2 S3Remote
Python uses a class with mutable state. Elixir uses an immutable struct passed through functions. Mutable fields (`fetched_refs`, `mode`, queued cmds) are managed by a `GenServer` wrapping the struct.

### 6.3 Concurrency
- Python uses `threading.Lock` + `concurrent.futures`. Elixir uses `Agent` (for `fetched_refs`) and `Task.async_stream` for parallel fetch.
- S3 lock acquisition retries (stale lock logic) are kept 1-to-1.

### 6.4 Stdin/stdout protocol
`main/0` functions become `escript` entry points. The `while True: readline()` loop becomes a recursive `loop/1` function.

### 6.5 Error handling
Python `try/except` → Elixir `try/rescue` or `with` + pattern matching on `{:error, reason}` tuples. Custom exceptions (`GitError`, `BucketNotFoundError`, `NotAuthorizedError`) become Elixir exception modules.

### 6.6 Logging
`logging.basicConfig` / `logger.info` → `Logger.configure(level: …)` / `Logger.info/1`.

### 6.7 AWS profile support
`boto3.Session(profile_name=…)` → ExAws config with `[profile: …]`; implemented as a helper that merges profile-based credentials into the ExAws request options.

## 7. Risks & Manual-Review Items

| # | Risk | Notes |
|---|------|-------|
| 1 | **ExAws profile support** | ExAws does not natively load `~/.aws/credentials` profile names the same way boto3 does. A helper using `:ini_file` or `ConfigProvider` is needed. Needs runtime testing. |
| 2 | **Conditional S3 writes (`IfNoneMatch: "*"`)** | ExAws S3 `put_object` supports custom headers; the `if_none_match: "*"` option must be passed via the `opts` keyword list. Verify against ExAws 2.x API. |
| 3 | **Multipart download** | `ex_aws_s3` supports multipart upload but download chunking is less explicit. May need `get_object` with range requests or rely on hackney streaming. |
| 4 | **`git bundle unbundle` stdout redirect to stderr** | Python passes `stdout=sys.stderr`; in Elixir `System.cmd` captures stdout — we redirect via Port or pipe logic. |
| 5 | **Interactive CLI prompts** | `manage.py` uses `input()` for interactive user prompts. In Elixir this maps to `IO.gets/1`. Behavior is preserved but not testable without a tty. |
| 6 | **Windows broken-pipe handling** | The `OSError errno 22` Windows workaround is not translated since Elixir/OTP handles broken pipes differently. |
| 7 | **Escript vs Mix tasks** | Elixir escripts bundle the BEAM and are invoked as standalone executables — a close equivalent to Python entry-points. Needs `erlang` + `elixir` on PATH at runtime. |
| 8 | **Test mocking strategy** | Python tests mock `boto3.Session.client`. In Elixir we define an `ExAws.Behaviour` mock with `Mox` and inject it. Requires a small refactor of S3 calls to go through a configurable module. |
